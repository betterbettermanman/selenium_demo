# 任务周期调度（每日/每月）设计

日期：2026-08-05  
状态：已确认（待实现）

## 背景

任务管理系统当前仅支持手动「启动」，完成后 `status=2`。实际业务存在两类续跑需求：

1. **四川学法（SCXF）等**：站点限制每日学分（如约 5 分），总目标更高（如 100 分），未完成任务需**多天被自动拉起**，达标后结束。
2. **四川智慧（SCZH）等**：课程按月更新，需**按月继续拉起未完成任务**；换哪门课由人工维护，系统不自动换课。

同时机器资源有限，需要**全局最大并发**，避免一次拉起过多浏览器。

## 目标

1. 任务级调度类型：`manual`（默认）/ `daily` / `monthly`。
2. 进程内定时器按配置时刻自动扫描并启动符合条件的任务。
3. 页面可「立即执行」某一类定时扫描（不等到点）。
4. `daily`/`monthly` 任务禁止普通手动启动，只能由定时扫描启动。
5. 全局 `max_running_tasks` 限制同时运行数。

## 非目标

- 已完成任务自动重置为未完成再跑
- 自动换课 / 自动改 `class_id` / `courses`
- 按网站编码写死调度策略（调度只看任务字段）
- 独立调度微服务、复杂优先级队列

## 方案选择

采用 **任务字段 + 进程内定时器（APScheduler 或等价）+ 全局并发上限**，复用现有 `start_task` 启动链路。

## 数据模型

### Task 新增字段

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `schedule_type` | 字符串 | `manual` | `manual` / `daily` / `monthly` |

历史数据无该字段时按 `manual` 处理。

### 调度配置（系统配置表或配置文件，实现期二选一，优先可 UI 修改）

| 项 | 说明 | 建议默认 |
|---|---|---|
| `max_running_tasks` | 同时运行任务上限 | `5` |
| `daily_time` | 每日触发时刻 | `08:00` |
| `monthly_day` | 每月触发日 | `1` |
| `monthly_time` | 每月触发时刻 | `08:00` |

## 启动权限矩阵

| schedule_type | 普通「启动」`POST /api/tasks/:id/start` | 定时器 /「立即执行定时」 |
|---|---|---|
| `manual` | 允许 | 不纳入扫描 |
| `daily` | **拒绝**（400） | 每日扫描纳入 |
| `monthly` | **拒绝**（400） | 每月扫描纳入 |

## 扫描规则

触发来源：

1. 定时到点（daily / monthly 各自 job）
2. 管理端「立即执行」某类型扫描
3. **定时任务结束/停止释放并发槽后**：仅补扫**同一调度类型**（月任务结束只补 monthly，不会拉起 daily），把因 `max_running_tasks` 未启动的候选继续拉起（短防抖合并连续结束）

每轮逻辑：

1. 计算 `slots = max_running_tasks - 当前运行中任务数`；若 `slots <= 0` 则本轮结束。
2. 查询候选：`schedule_type` 匹配本次类型 + `status=1` + 当前未在运行。
3. 按 `id` 升序（稳定、可预期）取前 `slots` 条。
4. 逐个调用现有 `start_task`（失败记日志，继续下一条）。
5. `status=2` 永不自动拉起；不重置、不改课程配置。

「运行中」判定与现有任务启动防重入一致（已有 runner 会话则视为在跑）。

## 前端

- 任务新增/编辑：调度方式三选一，默认「手动」。
- 任务列表：展示调度类型；`daily`/`monthly` 禁用或隐藏「启动」，文案提示「仅定时启动」。
- 工具入口：「立即执行每日扫描」「立即执行每月扫描」（或带类型选择的同一入口）。
- 设置页（或等价入口）：最大并发、每日时刻、每月日+时刻。

## 后端接口

| 接口 | 行为 |
|---|---|
| `POST /api/tasks/:id/start` | `schedule_type != manual` 时返回 400 |
| `POST /api/scheduler/run` | body `{ "type": "daily" \| "monthly" }`，立即跑一轮扫描，返回本轮尝试启动数/成功数/跳过原因摘要 |
| 配置读写 | 读取/更新 `max_running_tasks`、daily/monthly 触发配置；变更后刷新 scheduler job |

应用启动时注册 daily/monthly job。

## 业务对照

| 场景 | 配置 | 行为 |
|---|---|---|
| 学法刷满学分（约 20 天） | 任务 `daily`，未完成保持 `status=1` | 每天自动续跑，达标 runner 置 `status=2` 后不再拉起 |
| 智慧按月续学 | 任务 `monthly`，人工更新课程后保持未完成 | 每月（或点立即执行）拉起；换课人工 |
| 一次性课 | `manual` | 仅手动启动 |

## 错误处理

| 场景 | 处理 |
|---|---|
| 定时任务点普通启动 | 400，明确提示 |
| 已达并发上限 | 本轮不启新任务，日志记录剩余候选数 |
| 单条 start 失败 | 记日志，继续下一条 |
| 配置非法（并发≤0、时刻格式错） | 保存时校验拒绝 |

## 验收标准

1. 新建任务默认 `manual`，可手动启动；不出现在定时扫描结果中。
2. `daily`/`monthly` 点普通启动失败；到点或「立即执行」可启动未完成且有空位的任务。
3. 同时运行数不超过 `max_running_tasks`。
4. `status=2` 不会被定时再次启动。
5. 修改并发与触发时刻后，下一轮扫描按新配置生效。
