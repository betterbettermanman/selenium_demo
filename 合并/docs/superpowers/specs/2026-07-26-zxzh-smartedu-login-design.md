# 国家中小学智慧教育平台（ZXZH）登录设计

日期：2026-07-26  
状态：已确认（待实现）

## 背景

任务管理系统已支持乐山、眉山、内江、四川干部、四川学法、广元公需课等网站执行器。需新增 **国家中小学智慧教育平台**（`https://basic.smartedu.cn/`）。

该站点登录使用 **滑块验证码**（非现有图形 OCR 验证码），现有 runner 无滑块能力。

## 目标（本期）

1. 新增网站类型：编码 `ZXZH`，名称「国家中小学智慧教育平台」。
2. 自动登录：账号 + 密码 + 滑块验证码。
3. 登录成功后将任务标记完成（`status=2`）并关闭浏览器。
4. 使用用户提供的测试账号做本地联调验证（凭据不入库、不进代码仓库）。

## 非目标（下期）

- 选课 / 听课 / 刷进度 / 考试
- 短信验证码登录（`enable_sms_code=0`）
- 纯 API 刷进度
- 保证无头模式（`is_head=1`）下滑块稳定通过

## 方案选择

采用独立 `ZxzhTaskRunner`（继承 `SeleniumTaskRunner`），与现有站点执行器模式一致。

滑块识别采用 **分层兜底**：

1. **首选**：`ddddocr` 缺口匹配（项目已有依赖）+ Selenium `ActionChains` 拟人拖拽。
2. **兜底**：若 ddddocr 连续失败或对当前验证码厂商无效，则检索/接入其它开源滑块方案（如 OpenCV 边缘/模板匹配、其它缺口识别库），在 runner 内以可切换策略封装，优先保证登录打通。
3. 拖拽轨迹统一拟人化（加速→匀速→减速，轻微抖动），不写死固定像素距离。

## 架构

| 层 | 改动 |
|---|---|
| 数据 | 网站表新增：`ZXZH` / 国家中小学智慧教育平台 / `https://basic.smartedu.cn/` / `enable_sms_code=0`（UI 录入或 SQL 种子均可） |
| 执行器 | 新建 `backend/services/runners/zxzh_runner.py`，`@register_runner('ZXZH')` |
| 滑块 | runner 内实现滑块策略（ddddocr 首选；失败可换其它方案），调试截图落 `png/` |
| 注册 | `backend/services/runners/__init__.py` 导入该类 |
| 前端 | 无改动；沿用现有网站/任务管理 |

## 登录与会话

### 登录步骤

1. 打开 `https://basic.smartedu.cn/`。
2. 点击登录入口；若默认非账号密码登录，切换到账号密码 Tab。
3. 填写账号、密码。
4. 触发登录后等待滑块弹层出现。
5. 截取背景图与滑块图，计算缺口偏移并拟人拖拽。
6. 判定滑块是否通过；失败则刷新滑块重试（上限约 5 次；ddddocr 无效时切换兜底方案后再重试）。
7. 判定已登录后：`status=2`，关闭浏览器。

### 登录态判定

实现时探测可用信号（取其一即可）：

- cookie / localStorage / sessionStorage 中的 token 类字段
- 页面出现「个人中心 / 退出 / 用户名」等已登录标识
- URL 离开登录页且不再出现登录表单

### 会话硬约束

- 本期不做课程播放，登录成功即收尾，无需多窗口会话管理。
- 测试账号密码仅通过任务/网站账号配置传入，禁止硬编码进仓库。

## 错误处理

| 场景 | 处理 |
|---|---|
| 滑块失败 | 刷新重试，上限约 5 次；ddddocr 无效则切换其它滑块方案后继续重试 |
| 账号密码错误 | 记错误日志，任务失败 `status=1` |
| 找不到登录入口/表单 | 超时失败，`status=1` |
| 用户手动停止 | 现有 `request_stop`，关闭浏览器 |

### 收尾

- 登录成功：`status=2`，关浏览器。
- 异常：必要时 rollback session，`status=1`，关浏览器。

## 测试计划

1. 网站管理新增 `ZXZH` 记录（或种子）。
2. 创建任务，使用测试账号（本地配置，不进仓库）启动。
3. 有头模式验证：能打开登录页、通过滑块、标记任务完成。
4. 故意输错密码：应失败并 `status=1`。
5. 滑块连续失败场景：日志可见重试与（必要时）方案切换痕迹。

## 风险与备注

- 智慧教育平台登录可能经 SSO / 第三方验证码组件，选择器与 iframe 结构需实测后固化。
- 无头模式对抗滑块能力弱，联调默认有头。
- 验证码策略可能更新；分层兜底降低单点失效风险，但不承诺长期 100% 通过率。
